B Code — Privacy Policy

Target Audience: 13+ Years (Students & Developers) 100% On-Device Local Data Guarantee

Last Updated: November 19, 2026 · Version 1.0.0 · Application: com.bcode.editor

B Code ("we", "our", or "the app") is an independent mobile code editor application developed for Android devices. We are committed to transparency and respecting your privacy. This policy outlines how information is handled when you use B Code.

1. Target Audience & Age Requirements

B Code is designed and intended for high school students, college students, university learners, and independent software developers aged 13 and older (13+ years).

The application is not directed toward children under 13 years of age, and we do not knowingly solicit or collect personal information from children under 13. If you believe a child under 13 has provided personal information through the app or support channels, please contact us immediately so we can delete it.

2. Local Data Guarantee (Zero Cloud Storage)

Your Code Belongs to You:

All source code, project files, assets, configurations, and terminal sessions created or imported into B Code are stored 100% locally on your device in app-private storage. We do not operate proprietary cloud servers to ingest, index, or back up your workspace files.

Your code is never uploaded to any server without your explicit and deliberate action (such as committing and pushing to your own GitHub repository).

3. Advertising & Google Mobile Ads (AdMob) Disclosure

To support free access to compilers, language runtimes, and continuous offline development for students, B Code displays non-intrusive advertisements provided by Google Mobile Ads (AdMob) (such as sponsor breaks prior to compiler downloads).

Google Mobile Ads may automatically collect and process certain data for ad delivery, fraud detection, and diagnostic reporting:

  • Google Advertising ID (AAID): A user-resettable unique identifier assigned by Google Play services used for advertising and attribution.
  • Non-Personally Identifiable Diagnostic Data: Device performance statistics, app crash metrics, general device type, operating system version, and mobile network carrier.
  • IP Address: Used strictly for approximate coarse geographic delivery (country/city level) and network security.

Crucial Guarantee: Your workspace files, source code, commit history, and editor contents are completely isolated from advertising SDKs and are never shared with or readable by Google AdMob or advertisers.

Users who purchase the B Code Pro Semester Pass enjoy a 100% ad-free experience, during which ad SDK requests are disabled.

4. How to Reset or Delete Your Advertising ID (AAID)

Android gives you complete control over your Advertising ID. You can reset or permanently delete your Advertising ID directly in your Android system settings:

  1. Open your Android device's Settings app.
  2. Tap Google (or go to Privacy & Security > Ads depending on your device brand and Android OS version).
  3. Under the "Services" or "All services" tab, tap Ads (or Ad privacy).
  4. Tap Reset advertising ID to generate a fresh, unlinked ID.
  5. Alternatively, tap Delete advertising ID to opt out of personalized advertising across all apps on your device.

5. Network Requests & Third-Party Integrations

B Code makes network connections only for explicit, user-initiated actions:

  • GitHub Integration: Connects to api.github.com and github.com via the OAuth Device Flow. Your access token is stored securely in encrypted storage protected by the Android Keystore. The token is transmitted solely to official GitHub endpoints over HTTPS. You can revoke this token at any time in Settings or on github.com.
  • Language Runtime & Compiler Downloads: Downloads verified runtime packages from official repositories on demand. Every package's SHA-256 cryptographic checksum is verified before extraction.
  • App Updates: Checks the public GitHub Releases API (api.github.com/repos/advaiti/b_code/releases/latest) to alert you when a newer version of the editor or compilers is available.
  • Termux Runner (Optional): If you choose to execute programs via Termux, execution occurs locally on-device. Workspace projects are synchronized solely to your local Termux cache.

6. Permissions Requested

  • INTERNET: Required for GitHub synchronization, compiler downloads, update checks, and ad delivery.
  • ACCESS_NETWORK_STATE: Required to verify connectivity before initiating runtime downloads.
  • com.termux.permission.RUN_COMMAND (Optional): Requested only if you explicitly choose to execute scripts through Termux.

B Code does not request broad device storage permissions (such as MANAGE_EXTERNAL_STORAGE or READ_EXTERNAL_STORAGE). File imports and exports use the Android Storage Access Framework (SAF), ensuring you only share specific folders or files you select.

7. Diagnostics & Crash Reporting

B Code maintains an offline crash log on your device to assist in troubleshooting. Diagnostic logs never leave your phone automatically. When you tap Settings > Report a Bug, the app drafts an email in your preferred email client with diagnostic information and optional screenshots that you review and send yourself.
