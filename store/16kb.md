# 16 KB page-size alignment — status and decision

Phone hardware is moving to 16 KB memory pages and Google Play requires new
apps and updates (targeting Android 15+) to support it. This page records what
is true for B Code today, which native library is the exception, and what the
release path is.

## The one exception: `git2dart_binaries`

B Code uses [git2dart] for the built-in, permission-free git client. Its
native part, `git2dart_binaries`, ships **prebuilt** `libgit2.so`,
`libssh2.so`, `libssl.so`, and `libcrypto.so` binaries with 4 KB ELF LOAD
alignment (`align 0x1000` / `2**12`), for every ABI, including 1.14.1 — the
current release (checked with `readelf -lW`, 2026-11-04).

Everything else in the app is fine: the app has no other native code aside
from the Flutter engine and plugins, which compile with NDK 28+ and are
16 KB-aligned by default.

Consequence: on a 16 KB device Android runs B Code in **16 KB backcompat
mode** — the app works, but the package manager shows a one-time "running in
16 KB backcompat mode" notice at first launch. Play's **pre-launch report**
will flag it. Since 1 November 2025 Google also enforces 16 KB support for new
apps and updates targeting Android 15+, so treat this as a launch blocker
until an internal-testing upload is accepted. It is policy debt that must be
tracked, not a hard-functionality break on the device.

## Decision for v1

Ship v1 as a GitHub Release APK, not through Play, because:

1. Rebuilding libgit2 + libssh2 + OpenSSL from source with
   `-Wl,-z,max-page-size=16384` in CI is the only way to fix it ourselves;
   upstream already bundles them as prebuilt AAR jniLibs and a local compile
   of that stack is a separate project, not one release pass.
2. Backcompat keeps the app functional on 16 KB devices (AGP 9.1 / Gradle 9.3
   zip-align uncompressed `.so`s at 16 KB boundaries by default, which is what
   backcompat requires), so a sideloaded APK runs.
3. Google Play is expected to reject an upload that targets Android 15+ with
   these libraries until the rebuild lands. Do not promise a Play launch before
   an internal-testing upload is accepted.
4. The alternative — cutting the git feature from v1 — removes the headline
   integration for the store listing.

## Follow-up (tracked)

- Watch `git2dart_binaries` releases for an upstream 16 KB build; the CI
  workflow (`.github/workflows/build-apk.yml`) has an alignment report step
  that prints ALIGNED/UNALIGNED, so a dirty build cannot be missed.
- When that happens, or if Play rejects a submission over this page, restore
  policy-compliant state by compiling the three libraries with
  `-Wl,-z,max-page-size=16384` locally in the workflow.

[git2dart]: https://pub.dev/packages/git2dart_binaries
